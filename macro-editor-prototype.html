Option 1: Stacked Layout (Current)
The form is positioned above the list. Users scroll down to see their macros after creating/editing. This is your current implementation.

Pros

  • Simple, linear flow
  • Form is prominent and easy to find
  • Works well for creation-heavy workflows
  • Mobile-friendly (single column)

Cons

  • Requires scrolling to see macro list
  • Form takes space even when not in use
  • Hard to reference macros while editing
  • List gets pushed down, less visible

Option 2: Side-by-Side Layout
Form and list positioned side by side. Users can see both simultaneously without scrolling.

Pros

  • No scrolling needed to see both areas
  • Can reference macros while editing
  • Good use of horizontal space
  • Clear visual separation

Cons

  • Less space for form and list content
  • Form may feel cramped
  • Poor experience on narrow screens
  • Both compete for attention

Option 3: Master-Detail Pattern
List on the left (master), form on the right (detail). Classic pattern for edit-heavy workflows. Form only shows when creating new or editing existing macro.

Pros

  • Natural selection-to-edit flow
  • List always visible and prominent
  • More space for form when editing
  • Familiar pattern (email clients, etc.)
  • Great for browsing and editing

Cons

  • List sidebar takes permanent space
  • "Create new" action less discoverable
  • More complex state management
  • Needs collapse behavior for mobile

Option 4: Drawer/Slide-out Panel
List is the primary view. Form slides in from the side when creating/editing. The form is an overlay that doesn't push content around.

Pros

  • List gets full focus by default
  • Form doesn't take space when not needed
  • Clear visual separation of modes
  • Smooth transitions possible
  • Browse-first, edit-when-needed pattern

Cons

  • Form covers part of the list
  • Can't see both simultaneously
  • More complex to implement
  • Requires backdrop/overlay handling

Option 5: Tab-Based Separation
Separate the form and list into distinct tabs. Users switch between "Browse Macros" and "Create/Edit Macro" modes.

  • Simple to implement

  • Requires tab switching to compare
  • Edit flow requires switching tabs
  • May feel like extra steps

Recommendation

For your use case, I recommend Option 3 (Master-Detail Pattern), here's why:

  • Natural workflow: Users browse macros, select one to edit, or create new. This pattern matches that mental model perfectly.
  • List prominence: The macro list is always visible, making it easy to browse, search, and select.
  • Context switching: Form only appears when needed (creating or editing), reducing visual clutter.
  • Familiar pattern: Users are already familiar with this from email clients, file managers, and settings panels.
  • Scalability: Works well whether you have 5 macros or 50 macros.

Secondary option: Option 4 (Drawer) if you want to keep the list-first approach but need more flexibility. The drawer pattern is modern and keeps the form out of the way until needed.

Avoid: Option 5 (Tabs) may add unnecessary friction since users need to switch tabs to edit, breaking the flow.
